Glossary in plain words

What the words on this site mean. If you forget one of them, look here.

How a website works

Browser

The program you open websites in: Chrome, Safari, Firefox.

Server

A computer that is always on and connected to the internet. The website's program runs on it.

Request, response and HTTP

The browser asks the server for a page: that is a request. The server sends it back: that is a response. HTTP is the set of rules they use to talk.

Frontend

Everything you see on the page: text, buttons, design. It runs in the browser.

Backend

The hidden part of a website: a program on the server that receives the request, finds the data and prepares the response. This is where Python works.

Route

A rule for which address opens which page. For example, the address /contacts opens the contact page.

HTML

The content of a page: headings, paragraphs, links, images.

CSS

The look of a page: colours, fonts, layout of blocks.

JavaScript

A programming language that runs in the browser. It brings the page to life: buttons, menus, form checks.

127.0.0.1, localhost and port

The address 127.0.0.1 (also called localhost) means “this same computer”. A port is the number of the “door” a program is waiting behind. The address http://127.0.0.1:5000 opens the site running on your machine through door 5000. Other people cannot see it.

Status codes: 200, 404, 405

A number at the start of the server's response. 200 means all is well and the page was sent. 404 means there is no such address. 405 means the address exists but cannot be used this way: for example, sending a form (POST) to a place you can only view (GET).

JSON

A text format for exchanging data between programs. It looks like a Python dictionary: {"title": "Buy bread", "done": false}. This is how APIs respond.

CSRF

An attack in which another site secretly submits a form to your site on behalf of a user. The defence is a secret token in every form: Django adds it with the {% csrf_token %} tag.

Python and tools

Python

A programming language with simple rules. It is used for websites, data analysis and automation. Lessons from scratch.

Framework

A ready-made set of tools for building a website. With it you do not have to write everything yourself. Framework comparison.

Django

A big framework. It can do password login, an admin panel and data handling right away. Named after the guitarist Django Reinhardt.

Flask

A small framework. It gives you only the basics, and everything else is added as needed. Good for a first website.

Terminal

A window where you give the computer commands as text instead of with the mouse. On Windows it is PowerShell or Command Prompt, on macOS and Linux it is Terminal.

pip

A program that downloads and installs packages for Python. The command pip install flask installs Flask.

Virtual environment (venv)

A separate folder with the packages of one project. Packages of different projects do not get in each other's way. Created with the command python -m venv .venv.

View

A function that receives a request and returns a response. In Flask it is called a route handler, in Django a view.

Template

An HTML page with gaps that the program fills with data. For example, the title of a task is put in place of {{ title }}. Section on templates.

Data

Database

A store of records where data is easy to find and change: users, products, orders. Section on databases.

SQL

A language for querying a database. For example: “show all tasks that are not done yet”.

SQLite

A simple database stored in a single file. Handy for learning and small projects.

ORM

A way to work with a database in Python without writing SQL queries by hand.

Model

A description of a database table in Python: which fields a record has and of what type. For example, a task has a title and a “done” mark.

Migration

A written instruction for how to change the tables in a database: add a table or a field. In Django, makemigrations creates it and migrate applies it.

CRUD

The four basic actions with records: create, read, update and delete. Almost every website has them.

Working on a project

API and REST API

The way programs talk to each other. For example, a weather app gets data from a server through an API.

Git

A program that keeps the history of changes in your code. You can go back to any version. Section on Git.

Deploy

Putting a website on the internet so other people can open it. How to publish a site.
