Басты бет / Авторизация

Сайт пайдаланушыны қалай таниды

Аутентификация «бұл кім?» деген сұраққа, авторизация «оған не рұқсат?» деген сұраққа жауап береді. Құпиясөздерді сақтауды, сессияларды және жабық беттерді талдаймыз.

Құпиясөздер тек хеш түрінде сақталады

Хеш — кері қайтарылмайтын із. Дерекқорды ұрласа да, онда нақты құпиясөздер болмайды.

Құпиясөзді хештеу 
from werkzeug.security import check_password_hash, generate_password_hash

stored = generate_password_hash("секрет123", method="pbkdf2:sha256")

print("В базе лежит:", stored[:40] + "...")
print("Верный пароль:", check_password_hash(stored, "секрет123"))
print("Неверный пароль:", check_password_hash(stored, "qwerty"))
print("Два хеша разные:", stored != generate_password_hash("секрет123", method="pbkdf2:sha256"))

Кездейсоқ «тұздың» арқасында бір құпиясөздің хештері әртүрлі болады. Сондықтан бірдей құпиясөздер дерекқорда бірдей көрінбейді. Тұзсыз және баяулатусыз кәдімгі md5 немесе sha256 құпиясөздерге жарамайды. Нақты қосымшада әдісті көрсетпеуге болады: кітапхана әдепкі бойынша сенімді нұсқаны таңдайды.

Сессия: сайт кіргеніңізді қалай есте сақтайды

HTTP бұрынғы сұрауларды есте сақтамайды. Кіргеннен кейін сервер браузерге cookie береді, ал браузер оны келесі сұрауларға қоса жібереді.

Flask: кіру, жабық бет және шығу 
from functools import wraps

from flask import Flask, abort, redirect, request, session, url_for
from werkzeug.security import check_password_hash, generate_password_hash

app = Flask(__name__)
app.secret_key = "только-для-примера"  # в реальном проекте берите из переменной окружения

USERS = {"ernar": generate_password_hash("секрет123", method="pbkdf2:sha256")}

def login_required(view):
    @wraps(view)
    def wrapper(*args, **kwargs):
        if "user" not in session:
            return redirect(url_for("login"))
        return view(*args, **kwargs)
    return wrapper

@app.route("/login", methods=["POST"])
def login():
    name = request.form.get("name", "")
    stored = USERS.get(name)
    if stored is None or not check_password_hash(stored, request.form.get("password", "")):
        abort(401)
    session["user"] = name
    return redirect(url_for("profile"))

@app.route("/logout", methods=["POST"])
def logout():
    session.clear()
    return redirect(url_for("login"))

@app.route("/profile")
@login_required
def profile():
    return f"Привет, {session['user']}!"

client = app.test_client()
print("Без входа:", client.get("/profile").status_code)
print("Неверный пароль:", client.post("/login", data={"name": "ernar", "password": "x"}).status_code)
client.post("/login", data={"name": "ernar", "password": "секрет123"})
print("После входа:", client.get("/profile").text)
client.post("/logout")
print("После выхода:", client.get("/profile").status_code)

Неге назар аудару керек

  • Flask сессиясы secret_key кілтімен қол қойылған, бірақ шифрланбаған: онда құпия нәрселерді сақтамаңыз.
  • Логин қате болғанда да, құпиясөз қате болғанда да жауап бірдей, сонда бар логиндерді іріктеп табу мүмкін болмайды.
  • Шығу POST арқылы орындалады, сонда оны бөгде сайттан жай сілтемемен шақыру мүмкін болмайды.
  • Нақты сайтта кіру тек HTTPS арқылы жұмыс істеуі керек, ал әрекет санын шектеген жөн.

Django-дағы авторизация

Django-да пайдаланушылар, құпиясөздерді хештеу, сессиялар және дайын кіру беттері бұрыннан бар.

mysite/urls.py 
from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("accounts/", include("django.contrib.auth.urls")),
]
tasks/views.py 
from django.contrib.auth.decorators import login_required
from django.shortcuts import render

@login_required
def profile(request):
    return render(request, "profile.html", {"user": request.user})
mysite/settings.py 
LOGIN_URL = "login"
LOGIN_REDIRECT_URL = "profile"
LOGOUT_REDIRECT_URL = "login"

Кіру үлгісін өзіңіз жасауыңыз керек: templates/registration/login.html. Django-ның қазіргі нұсқаларында шығу тек POST арқылы жұмыс істейді, сондықтан оны сілтеме емес, батырмасы бар форма етіп жасаңыз.

Қол жеткізу құқықтары

Кіргеннен кейін пайдаланушының дәл өз деректерімен жұмыс істеп жатқанын тексеру маңызды.

Жиі қате — тек кірудің өзін тексеру. Егер /tasks/5/delete мекенжайы кез келген кірген адамға қолжетімді болса, нөмірді ауыстыра салып, біреудің тапсырмасын жоюға болады. Иесін әрқашан серверде тексеріңіз:

Django: тек өз тапсырмалары 
from django.contrib.auth.decorators import login_required
from django.shortcuts import get_object_or_404, redirect
from django.views.decorators.http import require_POST

from .models import Task

@login_required
@require_POST
def delete_task(request, pk):
    task = get_object_or_404(Task, pk=pk, owner=request.user)
    task.delete()
    return redirect("index")
